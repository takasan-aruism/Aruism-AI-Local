## 📋 意味階層観測システム（SHOS）仕様書 v1.0

### 1. プロジェクト概要

**名称**: Semantic Hierarchy Observation System (SHOS)  
**目的**: 概念の意味階層を統計的に観測し、客観的な分類体系を発見する  
**手法**: 複数回の生成による統計的パターン抽出

### 2. システム構成

```yaml
components:
  - generator: LLM（Q4/Q6）による階層生成
  - observer: 統計的パターン抽出
  - analyzer: 結果分析・可視化
```

### 3. 処理フロー

```
入力（概念リスト）
    ↓
軸の探索（10-20軸）
    ↓
各軸での反復生成（30-100回）
    ↓
統計的分析
    ↓
安定構造の抽出
```

### 4. API仕様

```python
# 基本インターフェース
class SemanticObserver:
    def explore_axes(self, concept: str, n: int = 10) -> List[str]
    def observe_axis(self, concept: str, axis: str, iterations: int = 50) -> AxisResult
    def analyze_patterns(self, results: List[AxisResult]) -> StableHierarchy
```

### 5. データ形式

```json
{
  "concept": "存在",
  "axis": "物質性",
  "iterations": 50,
  "raw_results": [...],
  "frequency_map": {
    "物質的": 0.94,
    "非物質的": 0.92
  },
  "stable_hierarchy": {
    "threshold": 0.9,
    "structure": [...]
  }
}
```

### 6. 実行パラメータ

```yaml
model_config:
  primary: "Q4_K_M"  # 速度優先
  validation: "Q6_K"  # 検証用
  
generation_params:
  temperature: 0.4-0.8  # 軸により調整
  max_tokens: 200      # 説明なし
  format: "simple_list" # 番号のみ
  
sampling_strategy:
  pilot_iterations: 10
  main_iterations: 30-50
  convergence_check: true
```

### 7. 出力仕様

```python
# 最小出力形式（高速処理用）
"1.物質的\n2.非物質的\n  2.1.精神\n  2.2.概念"

# 結果オブジェクト
{
  "converged_at": 35,  # 収束した試行回数
  "confidence": 0.92,   # 統計的信頼度
  "primary_patterns": [...],
  "variations": [...]
}
```

### 8. エラー処理

- 生成失敗: 3回リトライ後スキップ
- 収束しない: 最大試行回数で打ち切り
- メモリ不足: バッチサイズ自動調整

### 9. 使用例

```python
# 基本的な使用
observer = SemanticObserver(model="Q4")
axes = observer.explore_axes("存在")
results = observer.observe_axis("存在", "物質性", iterations=50)

# バッチ処理
for concept in concept_list_352:
    for axis in primary_axes:
        result = observer.observe_axis(concept, axis, 30)
        save_result(result)
```

### 10. パフォーマンス目標

- 1軸×50回: 15分以内（Q4）
- 10軸×30回: 2.5時間以内
- メモリ使用: 8GB以内

```python
from dataclasses import dataclass
from typing import List, Dict, Optional
from datetime import datetime

@dataclass
class AxisObservationResult:
    """単一軸の観測結果"""
    concept: str
    axis: str
    iterations: int
    temperature: float
    model_type: str
    timestamp: datetime
    raw_outputs: List[str]  # 生の出力
    parsed_hierarchies: List[Dict]  # パース済み階層
    frequency_map: Dict[str, float]  # 出現頻度
    convergence_iteration: Optional[int]  # 収束した回数
    stable_patterns: List[Dict]  # 90%以上で出現するパターン

@dataclass
class BatchResult:
    """バッチ処理結果"""
    total_concepts: int
    total_axes: int
    total_iterations: int
    start_time: datetime
    end_time: datetime
    results: List[AxisObservationResult]
    summary_statistics: Dict
```

### 5. API呼び出し形式

```python
# LLM APIへのリクエスト形式（docker-compose.ymlのポート8081）
def generate_hierarchy(self, concept: str, axis: str, temperature: float) -> str:
    prompt = f"{concept}を{axis}の観点で階層化（番号とラベルのみ）："
    
    response = requests.post(self.api_url, json={
        "messages": [{"role": "user", "content": prompt}],
        "temperature": temperature,
        "max_tokens": 200,
        "stream": False
    })
    return response.json()["choices"][0]["message"]["content"]
```
