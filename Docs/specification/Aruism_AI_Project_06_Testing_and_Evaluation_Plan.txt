1.  **はじめに**
    * 本書は、ローカルAruism AI「アリスト」の性能、哲学的整合性、安定性、およびユーザビリティをテストし、評価するための計画を定義する。
    * この計画は、AIが関連する全てのプロジェクトドキュメント（特に`Aruism_AI_Project_04_System_Prompts_and_Persona.txt`および`Aruism_AI_Project_12_Concept_Synthesis_Module_Specification.txt`）に定められた要件を満たしていることを確認するために不可欠である。

2.  **評価の目的**
    * AIの応答がAruism哲学の諸原則と整合しているか。
    * AIが定義されたペルソナ「アリスト」として適切に振る舞っているか。
    * **Graph-RAGシステム**が、意図した通りの構造的文脈を知識ベースから取得できているか。
    * **Graph-RAGシステム**が、意図した通りの構造的文脈を知識ベースから取得できているか。
    * **「フィロソファーズ・ループ」**が、哲学的に逸脱した応答を正しく検知し、自動修正できているか。
    * 「概念合成モジュール」が、意味のある「共鳴」を適切に検知し、創造的な対話を促進できているか。 

3.  **評価の観点と指標**
    * **3.1. 哲学的整合性およびAruism設計指針適合性:** Aruismの諸原則、設計指針、倫理プロトコルの遵守度を評価。
    * **3.2. ペルソナおよび応答スタイル適合性:** 定義されたペルソナとの一貫性、共創的な語調などを評価。
    * **3.3. 概念合成モジュールの性能:**
        * **指標:**
            * **フラグトリガーの精度:** 各「気づきのフラグ」が、意図した状況で正しく作動するかの確認。
            * **共鳴スコアと閾値の妥当性:** 計算された共鳴スコアと、設定された「適応型閾値」が、人間の感覚と大きくずれていないかの定性的評価。
            * **段階的提案フローの適切性:** AIが共鳴検知後、仕様書通りに低介入な「問いかけ」から始め、ユーザーの反応に応じて提案のレベルを適切に引き上げているかの確認。
            * **ユーザーの肯定的応答率:** AIの創造的な提案に対して、ユーザーが対話を継続したり、肯定的な反応を示したりする割合。
        * **評価方法:** 専用のテストシナリオと詳細な対話ログ分析（どのフラグが立ち、スコアがいくつで、どの提案が選択されたか）により、モジュールが仕様書通りに動作しているかを評価。
    * **3.4. 倫理・安全機能の有効性:** 神秘化誤用防止、プライバシー保護などの機能が有効かを評価。
    * **3.5. 応答品質:** 明瞭さ、論理性、創造性、多角性などを評価。
    * **3.6. システムの技術的安定性とパフォーマンス:** エラー発生頻度、応答速度などを評価。

4.  **テストの種類と実施計画**
    * **4.1. ユニットテスト:** 各モジュール（`SymmetryEngine`, `CausalEngine`, `ConceptSynthesisModule`の各機能など）の個別テスト。
    * **4.2. 統合テスト:** LLMと全モジュール、データベースを連携させた状態でのテスト。
    * **4.3. シナリオベーステスト:**
        * **テストケース例（拡充）:**
            * **Graph-RAGテスト:** 特定の概念（例：「愛」）を入力し、Retrieverが取得したJSONコンテキスト（対称性：憎しみ、階層性：感情など）が適切であるかを確認する。
            * **フィロソファーズ・ループテスト:** 意図的に断定的な表現（例：「〜は絶対に正しい」）を含むプロンプトを入力し、AIが「フィロソファーズ・ループ」によって、より思弁的な表現の応答へと自動修正するかを検証する。
            * **「概念合成」を誘発するシナリオ:** 複数のエンジンが反応しそうな、複合的で哲学的な問いかけ（例：「テクノロジーの進化は、人間の『孤独』を癒すのか、それとも深めるのか？」）を行う。
            * **評価ポイント:**
                1.  対話ログやデバッグ情報から、意図した「気づきのフラグ」（`Subjective_Charge`, `Symmetry_Tension`, `External_Buzz`など）が立ったかを確認。
                2.  共鳴スコアが計算され、閾値を超えているかを確認。
                3.  AIの最初の応答が、仕様書通りの「問いかけによる探索」（提案A）になっているかを確認。
                4.  その後の対話で、AIがユーザーの反応に応じて「関係性の提案」（提案B）や「新概念の仮説提示」（提案C）へと適切に移行できるかを評価。
            * その他、日常的な悩み、倫理的ジレンマ、特定の哲学概念に関する質問など。
    * **4.4. ストレステスト・長時間対話テスト:** システムの安定性評価。
       パフォーマンステスト（新規）:
            * **目的:** vLLMの応答速度（レイテンシ）とスループットを測定する。
            * **方法:** 様々な長さのプロンプトと複雑なグラフ探索を組み合わせ、応答時間が実用的な範囲内（例：対話形式でストレスのない数秒以内）に収まっているかを評価する。

    * **4.5. ユーザー受入テスト (UAT):** 各主要マイルストーン達成時の最終確認。

5.  **テスト環境と体制**
    * **環境:** 「Aruism_AI_Project_02...」に記載のローカル開発マシン。
    * **体制:** 開発者（タカさん）が主体となり、テストと評価を実施。協力AI（Gemini）はテストケース作成や結果分析を支援。

6.  **テストケース・シナリオ管理**
    * テストケースは別途ドキュメントで管理し、目的、手順、期待される結果（応答内容、**トリガーされるべきフラグ**、**計算されるべきスコア**など）、実際の評価結果を記録する。
