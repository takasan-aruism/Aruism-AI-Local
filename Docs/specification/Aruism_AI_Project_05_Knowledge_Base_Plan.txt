1.  **はじめに**
    * 本書は、ローカルAruism AI「アリスト」の思考と応答の基盤となる知識ベースのアーキテクチャ、初期構築戦略、および動的な運用計画について定める。
    * 本計画は、プロジェクトの公式設計資料である「Aruism_AI_Project_11_Cognitive_Architecture_Design.txt」に完全に準拠し、その要点を計画として整理したものである。
    * 知識ベースの目的は、Aruism哲学を静的なデータとして保持するだけでなく、その哲学を体現し、成長し続ける「生きたオントロジー」を構築することにある。

2.  **知識ベースのアーキテクチャ**
    * **2.1. 基本構造:** システムは、真のグラフデータベース（Neo4j）を中核とする。これにより、存在間の複雑な「連動性」を忠実に表現する。
    * **2.2. オントロジカル・データモデル（シンボル核・言語表象モデル）**
        * **思想:** 知識の根源を、言語から切り離された「シンボル」が担い、言語はそれに紐づく「表象」として扱うことで、言語の曖昧性を克服する。
        * **`:Concept` ノード (意味の核):** あらゆるユニークな概念（「存在」）を一意のシンボルで管理する。`concept_id`, `symbol`, `category`等のプロパティを持つ。
        * **`:Expression` ノード (言語の器):** 各言語の表層的な単語やフレーズを格納し、`:EXPRESSED_AS`関係で`:Concept`ノードに紐づく。
        * **リレーションシップ (関係性の網):** `Symmetric_To`, `Is_A`, `Causes`といった関係性に加え、「京都大学名詞格フレーム」から得られる`所属格`などの文脈的関係性を定義する。
    * **2.3. 条件付き階層性:** 「存在の階層性」は、`Relationship`テーブル内の`Valid_Under_Axis_ID`フィールドによって実現される。これにより、階層が特定の「軸」の条件下でのみ有効となる、Aruismの哲学に沿った柔軟な構造を実装する。
    * **2.4. 哲学的整合性デーモン:** データベースの状態が常にAruismの諸原則（単一ルートの原則、連動性、対称性、対等性）に準拠しているかを能動的に検証するソフトウェアプロセス。AIの学習・成長過程における哲学的整合性をシステムレベルで保証する。

 **初期構築戦略（創世記プラン）**
    * **3.1. 目的:** 空の知識ベースに、創設者殿が定義した、アリズムの思想を反映する、核となる概念群とその基本関係（対称性）を構築する。
    * **3.2. 構築プロセス:**
        * **フェーズ1: 原初の概念の登録 (Genesis Import):**
            * `genesis_importer.py`を使用し、`AruismBaseDBTable.csv`から、約350のシンボルベース概念（`:Concept`）とその対称関係（`:Symmetric_To`）を創造する。
        * **フェーズ2: 既存知識によるエンリッチ (Knowledge Enrichment):**
            * `wordnet_importer.py`をリファクタリングし、フェーズ1で作成した`:Concept`ノードに、WordNetの`synset_id`、定義、階層関係（`:Is_A`）を「追記」する。
            * `sentiwordnet_importer.py`をリファクタリングし、`wordnet_synset_id`をキーとして、各`:Concept`ノードに感情スコアを「追記」する。
        * **フェーズ3: 文脈知識の統合 (Contextual Integration):**
            * `caseframe_importer.py`を実装・実行し、「京都大学名詞格フレーム」のデータをインポートする。これにより、既存の`:Concept`ノード間に、`所属格`のような、膨大な数の文脈的・連動性の関係性を構築する。
    * **3.3. 利用する主要データソース（入手済み）**
        * `AruismBaseDBTable.csv` (創設者殿によるキュレーション)
        * `wnjpn.db` (日本語WordNet)
        * `SentiWordNet_3.0.0.txt` (SentiWordNet)
        * `kyoto-univ-web-ncf-1.0.xml.gz` (京都大学名詞格フレーム)
        * その他、`BCCWJ`頻度リスト、`pn.csv`等の感情辞書。
 * **【v1.2 新規】3.4. 長期的な知識統合ロードマップ**
        * 以下のロードマップに基づき、知識ベースを継続的に拡張する。

        * **ステップ1: 意味の骨格と感情価（完了）**
            * **1.1 WordNet / 日本語WordNet:** `wordnet_importer.py`を用いて、`Genesis`で創造した核概念に、定義と階層関係を追記。 (✓ 実装・テスト完了)
            * **1.2 SentiWordNet:** `sentiwordnet_importer.py`を用いて、核概念に国際的な感情スコアを追記。 (✓ 実装・テスト完了)

        * **ステップ2: 文脈と連動性の獲得（次期タスク）**
            * **2.1 京都大学格フレーム:** `caseframe_importer.py`を実装し、概念間の文脈的な関係性を大規模に構築する。
            * **2.2 BCCWJ（現代日本語書き言葉均衡コーパス）:** `frequency_provider.py`を実装し、単語の一般性・専門性データを知識ベースに統合する。

        * **ステップ3: 外部巨大知識との連携（将来）**
            * **3.1 Wikipedia / DBpedia:** `knowledge_linker.py`を拡張し、百科事典的知識をリアルタイムAPI経由で参照する機能を強化する。
            * **3.2 Wikidata:** `knowledge_linker.py`を拡張し、構造化された事実情報を参照する機能を強化する。

        * **ステップ4: 多言語と常識への展開（研究開発）**
            * **4.1 BabelNet:** 多言語間の概念マッピングを実現し、AIの思考をグローバル化する。
            * **4.2 日本語フレームネット:** 「売買」のような、より高度な状況・行為のフレームを知識として導入する。
            * **4.3 ConceptNet:** 「AはBに使われる」といった、より常識的な知識を導入する。


4.  **動的な運用と成長（生きたオントロジー）**
    * **4.1. 存在の創造 (概念合成モジュール):** AIが対話を通じて、この豊穣な知識ベースの中に新たなパターン（共鳴）を発見した場合、新しい`:Concept`や`:Relationship`の創造を提案する。
    * **4.2. 主観性の表現 (個人的・文脈的オーバーレイ):** `User`ノードと連携し、ユーザーごとの解釈や価値観を、既存の知識に上書きすることなく、追加のレイヤーとしてグラフに記録する。
    * **4.3. 存在の了解 (グラフのクエリとトラバーサル):** AIの推論プロセスは、特定のグラフトラバーサルアルゴリズム（類推発見、因果連鎖、構造分解など）によって定義される。クエリは常に特定の「軸」の文脈内で実行され、AIの「視点」を動的に変更する。

5.  **データ管理方針**
    * 本知識ベースを構成するデータの具体的な保存形式、格納場所、バックアップ方針、セキュリティ対策については、「Aruism_AI_Project_09_Log_and_Data_Management_Policy.txt」（最新版）の定めに従う。
    * 特に、個人的・文脈的オーバーレイに関連するユーザーデータは、最高のプライバシー保護基準をもって管理される。
