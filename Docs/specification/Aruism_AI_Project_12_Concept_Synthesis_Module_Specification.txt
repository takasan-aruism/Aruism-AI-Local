# ドキュメント名: Aruism AI Project - Concept Synthesis Module Specification
#                 (アリズムAIプロジェクト - 概念合成モジュール仕様書)
# プロジェクト: Local Aruism AI Development
# バージョン: 1.0
# 最終更新日: 2025-06-19
######################################################################

1.  **目的**
    * 本モジュールは、AI「アリスト」がユーザーとの対話や知識ベースの自己分析を通じて、複数の既存概念間の予期せぬ「共鳴」を検知し、それに基づき新しい概念、関係性、あるいは視点を「創造」またはその提案を行うことを目的とする。
    * これは、Aruism哲学における「存在の創造」を、AIの能動的な機能として実装する試みである。

2.  **設計原則**
    * **2.1. 「共鳴」の検知モデル:** 創造のきっかけとなる「共鳴」は、単一の要因ではなく、複数の独立した分析エンジン（SymmetryEngine, HierarchyEngine, CausalEngineなど）が、同じ対象に対して同時に「意味のある」と反応する、予期せぬパターンとして検知される。
    * **2.2. Aruism哲学との整合性:** 本モジュールの全てのロジックは、Aruismの諸原則（対等性、対称性、連動性、階層性、非実在性など）と整合していなければならない。
    * **2.3. ユーザーとの共創:** 本モジュールは、AIが一方的に新しい概念を創造・提示するのではなく、ユーザーの内省を促し、共に対話を深める中で新しい意味や価値を「共に創り出す」ことを目指す。

3.  **「気づきのフラグ」と「重み」の定義 (v1.0)**
    * 「共鳴」を検知するため、以下の「気づきのフラグ」を定義する。各フラグの重みは正規化され、その合計値と多様性によって共鳴の強さを判断する。

| エンジン/分析 | フラグ名 | 重み (正規化値) | 条件（トリガー） | Aruism原則との関連 |
| :--- | :--- | :--- | :--- | :--- |
| **SubjectivityEngine** | `Subjective_Charge` | **0.35** | ある概念に対し、ユーザーが強い主観的価値（sentimentスコアの絶対値 > 0.75など）を紐づけている。 | **個人の「ある」の尊重** |
| **SymmetryEngine** | `Symmetry_Tension` | **0.25** | 対話の中で、対称的な概念（例：善と悪）が頻繁に対比・言及され、その間に緊張関係が生じている。 | **存在の対称性** |
| **HierarchyEngine** | `Cross_Hierarchy` | 通常は関連しない、異なる階層に属する概念同士が、ユーザーによって意図的に結びつけられている。 | **0.25** | **存在の階層性** |
| **CausalEngine** | `Causal_Endpoint` | ある概念が、多くの原因の終着点、または多くの結果の始点として、因果の結節点になっている。 | **0.2** | **存在の連動性** |
| **KnowledgeLinker** | `External_Buzz` | ある概念が、外部知識ソースで最近活発に議論されている。（編集量、話題性などを複合的に評価） | **0.2** | **存在の連動性（社会的）** |
| **(対話分析)** | `Metaphor_Usage` | ユーザーが、非標準的で創造的な比喩表現を用いている。（WordNetにない修飾関係など） | **0.2** | **存在の創造** |
| **(対話分析)** | `Axis_Diversity` | ユーザーが、単一の概念を複数の「軸」（例：倫理軸、芸術軸）から多角的に語っている。 | **0.2** | **軸** |
| **(対話分析)** | `Temporal_Echo` | 過去の対話で登場した概念が、現在の対話で異なる感情や文脈で再登場し、意味の変容が起きている。 | **存在の連動性（時間軸）** |
| **FrequencyProvider** | `Rarity_Focus` | 一般的には出現頻度の低い専門的な単語を、ユーザーが意図を持って頻繁に使用している。 | **0.1** | **関心の指標** |

4.  **共鳴検知ロジック**
    * **4.1. スコア計算:**
        * `Resonance_Score = Σ(各フラグの重み) + Diversity_Bonus`
        * `Diversity_Bonus`: 3種類以上の異なるエンジン/分析からフラグが立った場合に、ボーナススコア（例: +0.05）を加算する。
    * **4.2. 適応型閾値:**
        * 共鳴イベントをトリガーする閾値は固定ではなく、ユーザーの習熟度や対話モードに応じて変動させる。
        * **初期設定例:**
            * 初心者ユーザー（セッション < 10）: 閾値 = 0.4
            * 熟練ユーザー（セッション >= 10）: 閾値 = 0.6
            * 対話モード「哲学モード」選択時: `Cross_Hierarchy`フラグの重みにボーナス（例: +0.05）
    * **4.3. フラグ間の相関補正（将来的な拡張）:**
        * 特定のフラグの組み合わせ（例: `Symmetry_Tension`と`Metaphor_Usage`）に対して、特別なボーナスやペナルティを適用するルールを導入する。

5.  **イベント発生後のAIの行動フロー**
    * 共鳴スコアが閾値を超えた場合、以下の段階的なアプローチでユーザーとの対話を試みる。
    * **段階1：問いかけによる探索（低介入）**
        * **条件:** 共鳴スコアが閾値をわずかに超えた場合。
        * **行動:** AIは新しい概念を断定せず、ユーザーの内省を促すオープンな問いを投げかける。
        * **例:** 「先ほどから『A』と『B』について頻繁にお話しされていますね。この二つの間には、何か特別な繋がりがあるように感じますか？」
    * **段階2：関係性の提案（中介入）**
        * **条件:** 段階1へのユーザーの応答が肯定的、または共鳴スコアが中程度の場合。
        * **行動:** AIは、既存の概念間に新しい関係性を定義することを提案する。
        * **例:** 「『A』と『B』は、単に対立するだけでなく、互いを定義し合う『共鳴的連動性』という関係にある、と考えることはできないでしょうか？」
    * **段階3：新概念の仮説提示（高介入）**
        * **条件:** 段階2へのユーザーの応答が肯定的、または共鳴スコアが非常に高い場合。
        * **行動:** AIは、共鳴している状態そのものに、新しい名前を与えることを提案する。
        * **例:** 「その『A』と『B』が強く響き合っている状態を、仮に『C』という新しい概念として名付けてみませんか？」
    * **補足事項:** 全ての提案には、「これはあくまで私の解釈の一つですが」といった、Aruismの「非実在性」を反映した注釈を添えることを検討する。また、Grok提案の「遊び心（軽いユーモアやASCIIアート）」も、ユーザー体験向上のためにオプションとして導入を検討。

6.  **実装上の考慮事項**
    * `Metaphor_Usage`の判定には、spaCy等による依存構文解析と、WordNetやTF-IDFによる共起頻度の組み合わせを検討。
    * `External_Buzz`の判定には、Wikidata APIへのリアルタイムアクセスの負荷を考慮し、Redis等によるキャッシュ機構の導入を推奨。
    * 本モジュールの動作ログは、共鳴スコア、トリガーとなったフラグ一覧、AIが選択した行動（段階1〜3）などを詳細に記録する。
